# Структурированные расписания: часы работы, пиковые часы, график уборки

Дата: 2026-09-04. Статус: дизайн утверждён пользователем в разговоре.

## Зачем

Три поля блока «Operating Schedule» (III.1) — свободный текст: «Lounge
Operating Hours» (III.1.1), «Peak Hours» (III.1.3), «Deep Cleaning Schedule»
(III.1.4). Операторы пишут по-разному, дни недели перечисляют вручную,
разрывные интервалы («01:00–11:00 и 12:00–23:00») и закрытые дни выражают
словами. Команда потом тратит время на приведение к одному виду. Нужно
нормализовать и хранение, и заполнение: структура вместо текста, быстрое
заполнение недели одним действием, копирование дня, лёгкая правка.

Решения пользователя (в разговоре): вариант со структурированными типами
поля (не конструктор текста и не семь полей); ночные интервалы через полночь
НЕ поддерживаются — оператор разбивает их на два дня; тот же подход для всех
трёх полей; для уборки отдельная модель с периодичностью; экспорт — колонка
на день недели.

## Объём

| Ключ | Поле | Новый тип | Особенности |
|---|---|---|---|
| III.1.1 | Lounge Operating Hours | `weekHours` | состояния дня: круглосуточно / закрыто / интервалы |
| III.1.3 | Peak Hours | `weekHours` | состояния дня: нет пика / интервалы (без «круглосуточно») |
| III.1.4 | Deep Cleaning Schedule | `cleaningSchedule` | периодичность + детали |

Не меняются: III.1.2 «Seasonal schedule changes» (да/нет с пояснением),
остальные поля, схема БД (`field_values.value` — `jsonb`, структура ложится
в ту же колонку), реестр.

Вне объёма: ночные интервалы через полночь как одна запись; часовой пояс
(время локальное для лаунжа, как и сейчас); перевод старых текстовых
ответов в структуру (автоматический разбор ненадёжен); праздничные дни и
сезонные исключения (остаются в III.1.2).

## Модель данных

### Общие типы

```ts
type Weekday = 'mon' | 'tue' | 'wed' | 'thu' | 'fri' | 'sat' | 'sun'
type Clock = string           // 'HH:MM', 24-часовой, '00:00'..'23:59', плюс '24:00' только как конец
type Window = { from: Clock; to: Clock | null }   // to === null — интервал не дописан
```

Правила интервала (`Window`): `from` — валидное время `00:00`–`23:59`;
`to` — валидное время `00:01`–`24:00` или `null`; если `to` задан, `to > from`.
Правила списка интервалов дня: упорядочены по `from`, не пересекаются;
касание разрешено (`…–11:00` и `11:00–…`). Через полночь нельзя: конец
всегда больше начала в пределах суток; «22:00–02:00» оператор вводит как
«22:00–24:00» сегодня и «00:00–02:00» завтра.

### `weekHours`

```ts
type DayHours =
  | { kind: 'allDay' }                      // только там, где поле разрешает (см. hoursOptions)
  | { kind: 'none' }                        // «закрыто» у часов работы, «нет пика» у пиковых
  | { kind: 'windows'; windows: Window[] }  // 1..n интервалов
type WeekHours = Partial<Record<Weekday, DayHours>>   // отсутствие дня — «не отвечено»
```

Настройка на поле (`Field.hoursOptions`, только у типа `weekHours`):

```ts
type HoursOptions = {
  allDay: boolean                 // есть ли кнопка «круглосуточно»
  noneLabel: Localized            // подпись пустого состояния: «Closed»/«Закрыто» или «No peak»/«Нет пика»
}
```

III.1.1: `{ allDay: true, noneLabel: {en:'Closed', ru:'Закрыто'} }`.
III.1.3: `{ allDay: false, noneLabel: {en:'No peak', ru:'Нет пика'} }`.
Значение `allDay` у поля с `allDay: false` — отказ сервера.

### `cleaningSchedule`

```ts
type Nth = 1 | 2 | 3 | 4 | 'last'
type CleaningSchedule =
  | { cadence: 'daily'; windows: Window[] }
  | { cadence: 'weekly'; days: WeekHours }                       // дни без allDay; none = «нет уборки»
  | { cadence: 'monthly' | 'quarterly'; nth: Nth; weekday: Weekday; windows: Window[] }
```

«Ежеквартально» = тот же день в первом месяце каждого квартала (январь,
апрель, июль, октябрь) — фиксируется в тексте отображения, отдельного поля
месяца нет (YAGNI).

## Проверка на сервере (ворота)

Один чистый модуль `src/form-schema/schedule.ts` (без React/DOM, как
`contact.ts`): константы `WEEKDAYS`, `NTHS`; предикаты `isClock`,
`isValidWindow`, `windowsWellFormed` (порядок, непересечение);
`validateWeekHours(value, options)`, `validateCleaningSchedule(value)`
возвращают `ValidationResult`; предикаты полноты `weekHoursComplete(value,
options)`, `cleaningComplete(value)`; форматирование (см. ниже).
`validateField` получает `case 'weekHours'` и `case 'cleaningSchedule'` и
только вызывает эти функции.

Что отвергается при сохранении (тексты `Localized`, живут в `validation.ts`
рядом с `REQUIRED`): не-объект (кроме `null`/`undefined` = очищено — как у
контактных полей); неизвестный день / вид / периодичность / `nth`; время
не в формате ЧЧ:ММ; `to <= from`; пересекающиеся или неупорядоченные
интервалы; `allDay` там, где не разрешено; пустой список интервалов у
`kind: 'windows'`.

Что сохраняется, но делает анкету НЕПОЛНОЙ (правило полноты, не отказа):
интервал с `to: null`; не все семь дней отвечены у `weekHours`; у часов
работы все дни `none` (лаунж, закрытый всю неделю, — не ответ); у пиковых
и уборки ни одного интервала (у `weekly`-уборки — ни одного дня с
интервалами). Так черновик не теряется на полпути, а отправить недоделку
нельзя — тот же принцип, что у позиций услуг (`serviceItemAnswered`).

Полнота: `src/submissions/completeness.ts` сегодня считает поле отвеченным,
если оно «не пустое» (`isBlank`). Для новых типов появляется общее правило
`fieldAnswered(field, value)` в схеме (`form-schema`), которое для прежних
типов равно `!isBlank`, а для новых зовёт `weekHoursComplete` /
`cleaningComplete`; `missingItems` использует его. Одно правило — одно место.

Очистка значения командой (`null`) — допустима; поле становится
неотвеченным, у обязательного — снова «не заполнено».

## Заполнение

Компоненты в `src/web/`:

- `WindowsEditor` — список интервалов одного дня: пары `<input type="time">`
  (родной выбор времени на телефоне; шаг 5 минут; `24:00` вводится кнопкой
  «до конца дня» рядом с полем конца, потому что `<input type="time">` не
  принимает 24:00), кнопка «+ интервал», «×» у каждого. Новый интервал
  появляется с `to: null`.
- `WeekHoursEditor` — семь строк: подпись дня, кнопки состояния (тем же
  видом, что Да|Нет у услуг: `aria-pressed`): «24 часа» (если
  `allDay`), «<noneLabel>», «По часам»; под «По часам» — `WindowsEditor`.
  Быстрые действия: над сеткой «Одинаково всю неделю» (раскладывает
  понедельник на все дни; активна, когда понедельник отвечен), у каждой
  строки кроме первой «Как в предыдущем дне», над сеткой «Скопировать пн
  → будни» и «пн → выходные». Действия — чистые функции над `WeekHours`
  (`applyToAll`, `copyFrom`, `applyToWeekdays`, `applyToWeekend`) в
  `schedule.ts`, компонент только вызывает их.
- `CleaningScheduleEditor` — кнопки периодичности (ежедневно / еженедельно /
  ежемесячно / ежеквартально); ниже — `WindowsEditor` для ежедневной,
  `WeekHoursEditor` с `allDay: false` для еженедельной, для месячной и
  квартальной — два выбора (`nth`, день недели) и `WindowsEditor`. Смена
  периодичности переносит введённые интервалы туда, где это осмысленно
  (daily ↔ monthly ↔ quarterly — один список интервалов); при переходе в
  `weekly` и обратно интервалы начинаются пусто. Перенос — чистая функция
  `switchCadence` в `schedule.ts`.
- `FieldInput` получает `case 'weekHours'` и `case 'cleaningSchedule'` и
  рендерит соответствующий редактор с общим `label`/`hint`/`errorNode`.
  Тот же компонент работает в форме, на экране правок и в редакторе
  команды — как у всех полей.

Автосохранение: каждое изменение отправляет всё значение поля (как у
позиций услуг); отказ сервера показывается под редактором тем же
`.fix-comment`. Недописанный интервал не даёт отказа (см. выше), поэтому
красного мигания при обычном наборе нет.

Мобильный экран: строки дня в столбик, интервалы в столбик, кнопки состояния
шириной на всю строку; настольный — как есть у формы. Все новые цвета — с
тёмной парой; кнопки состояний берут стили `aria-pressed` у услуг.

Старые текстовые ответы: показываются как есть текстом с пометкой «в
свободной форме» (`Localized`) над пустым редактором; первое сохранение из
редактора заменяет текст структурой. На экране проверки такая строка
печатает текст и ту же пометку.

## Отображение (канонический текст)

`formatFieldValue` для новых типов зовёт `formatWeekHours(value, locale)` и
`formatCleaning(value, locale)` из `schedule.ts`:

- одинаковые соседние дни сжимаются: `Mon–Sat 00:00–23:59; Sun 03:00–23:59`;
  `Mon–Fri 24h; Sat–Sun Closed` (подпись пустого состояния — из
  `hoursOptions.noneLabel`); интервалы через запятую: `Mon 01:00–11:00,
  12:00–23:00`; неотвеченный день — `—`; недописанный интервал — `01:00–…`.
- уборка: `Daily 02:00–04:00`; `Weekly: Mon, Thu 02:00–04:00` (дни с разными
  интервалами — через `;`); `Monthly, 1st Monday 02:00–04:00`; `Quarterly,
  last Sunday 01:00–05:00`.
- по-русски: `Пн–Сб 00:00–23:59; Вс 03:00–23:59`, `Ежедневно…`,
  `Ежемесячно, 1-й понедельник…`, `Ежеквартально, последнее воскресенье…`.
- старый текст — как есть.

## Экспорт (xlsx)

`src/export/columns.ts`: поле типа `weekHours` даёт восемь колонок — `<key>
<label> — Mon` … `— Sun` и `<key> <label> — free text`; поле
`cleaningSchedule` даёт девять — `— Cadence`, семь дневных, `— free text`.
Ячейка дня — текст дня без имени дня (`00:00–23:59`, `24h`, `Closed`,
`01:00–11:00, 12:00–23:00`, пусто у неотвеченного). У уборки: ежедневно —
все семь дневных ячеек одинаковы, «Cadence» = `Daily`; еженедельно — по
дням, «Cadence» = `Weekly`; ежемесячно/ежеквартально — интервал в ячейке
своего дня недели, «Cadence» = `Monthly, 1st` / `Quarterly, last`. Старый
текстовый ответ — целиком в `— free text`, остальные ячейки пусты.
Раскладка ячеек — чистая функция `scheduleCells(field, value)` в
`schedule.ts`, экспорт её только вызывает. Golden fixtures колонок
обновляются вместе с кодом (состав колонок меняется сознательно).

Выгрузка отдельной анкеты (single-submission export) печатает
канонический текст одной строкой — как экран проверки.

## Шаги формы и сид

Поля остаются в блоке III.1 «Operating Schedule» (шаг 3 формы). Сид пишет
для III.1.1 полную неделю (`Mon–Sat 00:00–24:00`, `Sun 03:00–24:00`), для
III.1.3 два интервала в будни и `none` в выходные, для III.1.4
`{ cadence: 'daily', windows: [{ from: '14:30', to: '15:00' }] }`.
